# 005 面板

在 DeepSeek Harness Web 侧边栏打开 **Superagent** 以监督智能体。面板优先展示需要人工处理的工作，其次是系统健康状态和历史。本文建立在 [000 理念](000-philosophy.md)至 [004 提示词](004-prompts.md)之上。

## 三个问题

打开面板后，依次回答三个问题：

1. 现在有什么需要我处理？
2. 系统是否健康，是否在做正确的事？
3. 一项工作从 Trigger、Eval 到 Ticket 的历史是什么？

## 标签页

标签页遵循工作流程：**概览**、**来源**、**触发**、**评估**、**执行**和**设置**。仓库与账号设置成功前，概览会展示缺少的内容并链接到相关设置。

| 标签页 | 展示内容 |
| --- | --- |
| 概览 | 需要处理的 Ticket、系统问题、过去 24 小时的活动统计及 Executor 负载。每个区块链接到详情页 |
| 来源 | 来源状态、设置问题和非零计数。过滤的 Trigger 和丢弃的消息采用与概览相同的 24 小时窗口 |
| 触发 | 按已订阅、评估中、24 小时内的新 Trigger 或全部 Thread 筛选的 Thread。每个 Thread 按最新优先展示 Trigger、Decision 和 Subscription |
| 评估 | Decision 及其原因和匹配规则 |
| 执行 | Executor 状态、暂停处理，以及按打开、待处理、工作中、等待 Trigger 或已结束筛选的 Ticket。Ticket 详情展示操作、授权、等待的 Input、Subscription 和 Assignment |
| 设置 | 来源、评估、执行、提示词和部署。每组均包含保存历史 |

### 查看单条记录

丢弃的消息链接到其 Ticket；没有 Ticket 时链接到 Thread。来源页说明对话是否消失，或来源是否停止监听该对话。

仍由 Executor 负责的人类后续消息标为 **已送达工单**，不会经过 Eval。Thread 还展示交回原因和仅供上下文的订阅。**重新评估**可以将该后续消息送入 Eval，也可重试没有有效判断的 Trigger：被来源过滤的 Trigger、未完成的 Eval，或既无非停止 Decision 又无 Executor 确认的已送达消息。

Ticket 详情展示来源 Trigger、Decision 和原因、范围及 Policy 版本。Assignment 和次要详情折叠在即时操作下方。Input 发送失败，或 Ticket 在 `blocked` 或 `failed` Report 后等待人工处理时，可使用**重试**。已结束 Ticket 展示**拉取请求已合并**或**由人停止**等结果。

## 设置分组

- **来源：** 每个来源一张卡片，包含开关、字段及已验证的账号信息。GitHub 还提供新 Issue、拉取请求、评论及默认分支 CI 的接收全部开关。轮询和读取限制位于高级设置中。
- **评估：** 先展示 Policy 版本和规则，再展示**各来源**和评估设置。各来源标签包含允许名单、成员同步、准入表和机器人名单。同步在启动时和点击**立即同步**时运行。准入表区分接收范围、发送者名单状态和消息是否指向智能体。评估设置可选择接受模式、超时和研判模型。
- **执行：** Worker 模型、并发数、目录根路径、准备命令和禁止命令。点击可用变量可将其插入准备命令。
- **提示词：** **编辑**用于更改团队部分、内置部分和技能。**完整提示词**展示组装后的文本，并与已保存文本或默认值比较。**历史**列出版本。编辑过的内置部分标记为已更改，可重置；模板列出必需占位符。

  升级改变了已覆盖的默认内容时，该部分标记为**默认内容已更新**。面板在团队文本上方比较新旧默认内容；如果未记录旧默认内容，则比较团队文本和新默认内容。选择**保留我的内容**或**使用新默认内容**。已移除部分的覆盖项列在标签栏下方，并在下次保存时删除。
- **部署：** 展示启动问题及**重新检查**、状态目录和机器限制。保存的限制无需重启即可生效。DeepSeek Harness 插件管理器也提供相同页面。

## 搜索

页头搜索可根据文本、id、飞书消息 id 或已保存链接（如 GitHub 评论 URL）查找 Trigger。原消息中缺失的飞书链接，只有宿主在当前进程生命周期内读取后才能被搜索到。

搜索还可根据 `#12` 或 GitHub URL 等引用查找 Thread，并按标题或匹配的 Thread 查找 Ticket。

## 原则

1. **关注重要事项。** 每个元素都必须回答三个问题之一，否则移除。只有数字会改变监督者的行动时才显示。
2. **定义精确。** 类别具有可验证的定义，彼此互斥并覆盖所有情况，如 Ticket 阶段。标签说明条目在等待谁及需要什么，而不是显示内部状态码。
3. **每个概念只有一个位置。** 来源状态属于来源；Thread 和 Trigger 属于触发；Decision 属于评估；Ticket 属于执行。设置按所配置的概念分组。概览汇总这些页面并提供链接，而不成为另一个详情页。
4. **遵循领域结构。** 面板使用领域术语。内部标识只出现在折叠的详情中，能够解析名称时用名称代替标识。
5. **状态真实。** 数量等于其链接列表的长度，任何状态都不能与其他事实矛盾。
6. **默认安静。** 健康状态不占额外空间。问题必须可操作；一次网络错误不足以构成问题。需要人的条目直接提供相应操作。页面说明保持一句话，更多细节放在 (?) 提示中。破坏性操作需要确认。
7. **控件一致。** 使用 DeepSeek Harness 的设计令牌和控件行为。相同信息在整个面板中应有相同外观。每个设置块只有一个保存栏，且仅在有更改、正在保存或保存失败时显示。
